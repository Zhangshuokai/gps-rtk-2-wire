# NMEA 0183 要点（本机实测）

> 来源：本机实测抓包（`fixtures/um982_raw.txt`）+ 项目内 `app/protocol/nmea.py`。
> 通用 NMEA 0183 语义在此不赘述，只记录**本机相关的实测结论**。

## 1. 实际出现的语句

| 语句 | 来源日志（配置名） | 说明 |
| --- | --- | --- |
| `$GNGGA` | `GPGGA` | 定位：经纬高/解质量/卫星数/HDOP/差分龄期/基准站 ID |
| `$GNRMC` | `GPRMC` | 时间/日期/速度（节）/航迹角 |
| `$GPTHS` | `GPTHS` | 双天线航向（degrees True，语义无歧义，**航向主来源**） |
| `$GPGSV` | `GNGSV` | 卫星仰角/方位角/C-N0 |
| `$GPGSVH` | `GNGSVH` | 厂家高精度 GSV 扩展，**仅配在 COM3** |

**按需出现**：`$--GSA`（配置名 `GPGSA`，实发 `$GNGSA`）、`$--VTG`（配置名 `GPVTG`）。
二者本固件**支持**，只是默认未配，需用 `LOG` 开启（见下）。

## 2. 校验和

标准 NMEA `$...*hh`：`$` 与 `*` 之间所有字符逐字节异或（**不含起始 `$`**），
两位十六进制。实现 `nmea.compute_checksum()`；实测 1000+ 条**全部通过**。

> 注意与模块自身 `$command`/`$CONFIG` 不同：后者**把 `$` 也算进去**，用
> `nmea.checksum_inclusive()`。详见 [`unicore-ascii.md`](unicore-ascii.md) §4。

## 3. GSA / VTG 的配置名（易错，2026-10 实机确证）

裸名 `GSA`、`VTG` 的 `help` 返回 `not found`，但 **`GPGSA` / `GPVTG` 有效**：

```
help GPGSA ->  GPGSA [period time(second)], Description: NEMA DOP and active satelitltes...
help GPVTG ->  GPVTG [period time(second)], Description: NEMA Ground speed...
```

`LOG <port> GPGSA ONTIME <s>` 实发 `$GNGSA`（每星座一条，末尾为 NMEA 4.11 系统 ID）。

* **「卫星是否参与解算」可实现**——用 `$--GSA` 判定；本程序已解析（`nmea._parse_gsa`），
  「标准遥测输出」预设含 `LOG {PORT} GPGSA ONTIME 1`。未开启时界面如实标注
  `参与解算（GSA 未开启）` 并置 `—`，不臆造。
* **同一星座入解超过 12 颗时会拆成多条 `$GNGSA`**：厂家手册 Table 7-22 的 BDS 示例即
  两行（`...,01,03,...,39,...` 与 `...,40,45,59,60,...`），末尾 SysID 相同。它们属于同一轮，
  逐星入解必须**取并集**（`state.GnssState._merge_gsa`），否则最后一行会覆盖前一行。
* 速度/航迹角仍主要由 `$GNRMC` 提供（`GPVTG` 亦可作为备选来源）。
* 不要用裸名 `GSA`/`VTG` 判断固件能力——那只会得到 not found。

## 4. GSV 的分行方式（实机实测）

实测 2026-10 的模块**按信号频点分行**发 GSV：每条只含一个信号频点的卫星，且
`total,index` 都写 `1,1`，末尾带 NMEA 4.11 的信号 ID；仰角/方位可能为空、只有 C/N0：

```
$GBGSV,1,1,03,26,,,26,42,,,30,14,,,29,1*7B     信号 1
$GBGSV,1,1,03,26,,,27,42,,,28,14,,,23,8*75     信号 8
$GBGSV,1,1,01,10,,,26,B*01                     信号 B
$GPGSV,1,1,01,04,,,21,4*67                     信号 4
```

因此**不能**把 `index==1` 当作"整颗星座新的一轮"来清空——那样每条都会清掉前一条，
整颗星座只剩 1 颗。正确做法是按 **(星座, 信号 ID, GSV/GSVH)** 累积后取并集
（见 `state.GnssState._merge_gsv` 与 `GSV_STALE_S`）。GSVH 与 GSV 是两条独立日志，
不能互相替换。

## 5. 星座判定

talker 可能是分星座的（`GB`=北斗、`GP`=GPS…），也可能是组合 talker；不确定时按
**PRN 号段**推断：

| PRN 段 | 星座 |
| --- | --- |
| 1–32 | GPS |
| 65–96 | GLONASS |
| 301–336 | Galileo |
| 401–437 | 北斗 |

推断出的星座在界面以 `*` 标记；若模块对每个星座独立编号 PRN，推断可能不准。
未知/异常 talker 一律归为 `?`（talker 来自不可信串口字节，属注入面）。

## 6. 健壮性约定（不可信输入）

串口字节视为不可信：`nmea._float` 必须拒绝非有限值（`nan`/`inf`/`1e400`，
`int(inf)` 会抛 `OverflowError`）。实测

```
$GNGGA,000000,nan,N,...
$GNGGA,,,,,,1e400,...
```

会真的抛异常并杀死读线程；`serial_link._handle_raw_line` 外层必须兜住异常，
单条坏报文只跳过并计数，不中断接收。
